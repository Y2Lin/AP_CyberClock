## 源码修复说明

### v10.4.1：截屏改环形流式（真机 ERR SHOT 修复）

v10.4 的截屏在系统堆一次性 `malloc(240*320*2)`=150KB，真机最大连续空闲块不足，`shot_request` 必然失败并回 `ERR SHOT`（在真实设备上首次实测发现）。

| 文件 | 改动 |
|---|---|
| `main/usb_time_sync.c` | 整屏缓冲改为 3 格环形槽（每格 240×24 行×2B = 11.5KB，共 34.5KB，峰值内存约旧方案 1/4.4）：flush 拦截回调（渲染任务）把每个全宽 20 行条带拷入下一空槽并置满标志；USB 任务（消费者）打印协议头后按序排空满槽、2KB 一段写回。生产侧环满时 `vTaskDelay` 小睡背压（上限 2s），任一侧失败置 `s_shot_abort`，对侧在等待点看到即退出摘钩；`service()` 保留非活跃态兜底摘钩（防下次截屏把包装函数误存为原回调导致无限递归）。状态机：0 空闲 / 1 已挂钩待首块 / 2 流式 / 3 完成 / 4 失败 |

### v10.4：FAP_SCREENSHOT_V1 运行时截屏（社区发布助手的连接证明协议）

| 文件 | 改动 |
|---|---|
| `main/usb_time_sync.c/.h` | 新增 `FAP_SCREENSHOT_V1` 命令：收到请求后 USB 任务只在系统堆分配 240×320×2 输出缓冲并置请求标志；`usb_time_sync_snapshot_service()` 由 LVGL 定时器上下文调用（`cyber_clock.c` tick），临时包装显示刷新回调并整屏失效，借下一轮渲染的 20 行分块在送显前累积出完整原生 RGB565 帧，随后从 USB 以 1KB 块流回。发送窗口全局静默日志防字节混入像素流。**为什么不用 lv_snapshot**：本项目 LVGL 走 64KB 内置池，150KB 整屏帧池内必然分配失败；借道 flush 只读不改渲染路径。超时路径双保险：先置中止态（flush 回调见非采集态即不碰缓冲）再释放，钩子残留由 service 下一拍兜底卸载（否则下次截屏会把包装函数误存为"原回调"造成无限递归）。本版本 LVGL 9.2 无公开 flush getter，直接读私有结构字段（与 esp_lvgl_port 内部做法一致） |
| `main/cyber_clock.c` | `tick()` 每拍调用 `usb_time_sync_snapshot_service()`（无请求时仅读一个 volatile 标志即返回）；新增对应头文件包含 |

### v9.1（网页/脚本修复，固件不变）：USB 对时后关闭网页导致设备重启

| 文件 | 改动 |
|---|---|
| `tools/cyber-clock-sync/index.html` | 打开串口后调用 `port.setSignals({ dataTerminalReady: false, requestToSend: false })` 保持 **DTR/RTS 常低**；关闭端口前防御性再压一次。此前代码写的是 `{ dtr: false, rts: false }`——Web Serial 会静默忽略无效字段，等于从未生效 |
| `tools/cyber-clock-sync/usb-sync.py` | 打开串口后 `ser.rts = False; ser.dtr = False`（**先 RTS 后 DTR**：先降 DTR 会短暂经过 DTR=0 & RTS=1 的复位组合电平） |

原因：ESP32-C3 的 USB Serial/JTAG 控制器内置"下载复位"通路，会把主机**关闭串口时的 DTR/RTS 电平变化**解读为复位脉冲（与 esptool 刷机后硬复位同一条通路）。会话期间保持两线常低，关闭网页/脚本退出/点"断开"都不再产生电平变化，设备不会重启。固件二进制不变（仍为 v9），无需重新刷机。

- **蓝牙只属于时间同步页**：进页开广播、离页（跳表盘/进菜单/自动跳转）即停——v6 的"表盘内自动开关广播"策略整体迁移过来，语义更清晰，表盘待机零蓝牙功耗；
- USB 对时仍为常驻服务，任何页面可用；同步事件只驱动"当前页面的时间刷新"，**仅当处于同步页时**才安排 5 秒自动跳表盘（留时间给对端收最终 FFC2 通知）；
- LVGL 线程安全不变：BLE 回调只置标志，UI 刷新全部在定时器上下文；页面切换只发生在按键回调与定时器两个已持锁的上下文；
- 主题切换（表盘页 UP）四页面统一换色；未同步闪烁提醒（v7）在同步页与表盘页都生效。

### v7：重启后如实显示未同步（无 RTC 电池的诚实状态）

| 文件 | 改动 |
|---|---|
| `main/time_manager.c` | 初始化时检测重启：`last_sync_ms > 当前单调钟`（重启后单调钟归零，旧记录"在未来"）即判定恢复时间不可信，**清除 `synced` 标志并立即持久化** |
| `main/cyber_clock.c` | 未同步时时钟主文字每秒明暗闪烁（`LV_OPA_60`/`LV_OPA_COVER` 交替），一眼可见"时间未校准" |

设计要点：
- 修复前：断电重启后 `synced=true` 原样从 NVS 恢复，屏幕挂着 `SYNCED`、蓝牙通知与 USB `Q` 都报 `synced:true`——但设备没有 RTC 电池，显示的时间其实是停走的旧值，状态撒谎
- 修复后三处状态源一致（屏幕 / FFC2 通知 / USB `Q`），并联动 v6 省电策略：未同步 → 进时钟页自动开广播等待对时
- 对时一次（USB 或蓝牙）即恢复正常：文字停止闪烁、状态变 `SYNCED`

### v6：BLE 省电策略（未同步自动广播 / 同步后自动关 / 按键开关）

| 文件 | 改动 |
|---|---|
| `main/cyber_clock.c` | ① 进入时钟页仅在**时间不可信**（本次开机未同步过；重启后单调钟归零导致 `is_reliable()` 为假，同样触发）时自动开广播；② 检测 `sync_count` 边沿（BLE / USB 写时间均自增），新同步事件后 5 秒自动 `ble_time_sync_stop()`（断连+停广播+释放 NimBLE）；③ OK 短按由"重启广播"改为**开关切换**；④ 状态栏新增 `BT ADV / BT LINK / BT OFF` 指示 |

设计要点：
- 全部策略逻辑放在 LVGL 定时器 `tick()`（已持锁上下文）执行，`ble_time_sync_stop()` 为同步操作（等 host 任务退出），无跨任务风险；
- 延迟 5 秒再关，保证对端收完最终 FFC2 通知、`Q` 状态回读有窗口；
- 手动开启后不会被中途打断，直到下一次**新的**同步事件才再次自动关；
- 广播期间射频平均电流约 +1~3mA，自动关闭可显著延长电池续航。

### v5：新增 USB 串口对时（免蓝牙方案）

| 文件 | 说明 |
|---|---|
| `main/usb_time_sync.c`（新增） | 利用 ESP32-C3 USB Serial/JTAG 外设接收文本对时命令：`PING`→`PONG` 探活、`T <unix> [tz]`→`OK TS=… TZ=…` 设置时间与时区、`Q`→JSON 状态。任务阻塞在 `usb_serial_jtag_read_bytes()`，无轮询开销 |
| `main/usb_time_sync.h`（新增） | 模块头文件 |
| `main/main.c` | `app_main` 调用 `usb_time_sync_start()`，任意页面（含主菜单）均可 USB 对时，不依赖进入时钟页面 |
| `main/CMakeLists.txt` | 新增源文件与 `esp_driver_usb_serial_jtag` 依赖 |

线程安全设计（吸取 v4 教训）：
- 控制台输出经 `usb_serial_jtag_vfs_use_driver()` 切到驱动路径后，主机未连接时 VFS 写入**快速失败**（`usb_serial_jtag_write()` 检查 `is_connected()` 直接返回），驱动模式下单次阻塞上限 50ms 后丢弃字符——拔线不会卡死任何打日志的任务，不会复现 v4 类死锁；
- USB 对时不直接碰 LVGL：时钟页面每秒自行重读时间，对时后 1 秒内自然刷新。

配套工具：`web-sync.html` 新增"USB 线同步"标签页（Chrome/Edge Web Serial，浏览器直连 USB 对时，Mac 免蓝牙）；`usb-sync.py` 命令行脚本（pyserial，Mac/Windows/Linux 通用）。
