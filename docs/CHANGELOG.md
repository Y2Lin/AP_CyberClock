# Changelog

## Unreleased

- Firmware v10.5 (minimal-mode redesign, finalized design scheme C): the DOWN minimal mode is rebuilt per the finalized design mockup v4.2 — full-mode and minimal-mode widgets now live in two separate full-screen layer containers swapped wholesale on DOWN (the old implementation only hid a few decorative widgets, leaving the dial skeleton on screen; the new minimal layer contains no full-mode elements at all). The minimal layer shows only: the `HH:MM` 48px centered big digits (dual-color ghost trails and the unsynced breathing blink kept, plus a new soft glow breathing on the main digits — all disabled on the e-ink theme), a thin seconds progress underline pressed against the bottom of the digits (v4.4 visual: a 112px centered two-layer offset line — low-alpha secondary ghost track plus a primary fill at 70% brightness (80% on e-ink) advancing by elapsed seconds in the minute — held 8px below the digit baseline; no end cursor), the date line `YYYY-MM-DD  weekday` (16px uniform dim color, double-space separator — montserrat has no middle-dot glyph), and a low-battery red dot in the top-right corner appearing only below 20% SOC (slow-blink alert, steady on e-ink; driven by the v10.4.3-calibrated SOC). All five themes adapted; full-layer elements (glitch bursts, color bars, pixel heart, spectrum) never appear in minimal mode. The underline y=149/150 spacing to the digit baseline can be fine-tuned on hardware per the actual font metrics (noted in code). App partition 1,048,624 -> 1,050,320 bytes (+1,696, covering the v10.4.3 gauge module; verified on a local ESP-IDF v5.5.3 build — merged full image 1,115,856 bytes, DRAM 174,754 / 321,296 bytes at 54.4%).
- Firmware v10.4.3 (battery percentage calibration): fixed a systematically high battery readout — the CW2017 fuel gauge never received the actual cell profile, so its default generic Li-Po curve maps 3.92 V to 73% (typical-cell OCV sits around 60-70%). Added the pure-logic module `main/battery_gauge.c/h`: the chip SOC register is no longer trusted; the VCELL voltage is read and converted through a typical 4.2V Li-Po OCV table with piecewise-linear interpolation (3.92 V -> 68%), plus a 3-sample voltage median filter (drops out-of-range I2C readings) and display hysteresis (changes under 3 points stay off-screen; crossing the 20% low-battery threshold always passes immediately so the red alert and its clearance are never delayed). The 5-second dial refresh path now goes through the gauge; the 10-segment bar and low-battery red line behave unchanged. New host tests `tests/test_battery_gauge.c` cover key table points, global monotonicity, hysteresis edges, bad-sample rejection, and a discharge sequence. The OCV table is a typical curve and awaits refinement against the actual cell datasheet or a discharge calibration (battery item in `docs/TODO.md`).
- Added `docs/TODO.md` (+ Chinese pair): a next-task backlog for quick session restarts, recording the three follow-ups agreed after v10.4.2 — the minimal-mode redesign (design-first via an HTML mockup, no code until the design is approved), the battery-percentage calibration investigation, and publishing the `FAP_SCREENSHOT_V1` pitfall notes on an `AP_Sound_Test` branch. Registered in both documentation indexes.
- Firmware v10.4.2 (screenshot USB write fix, found on real hardware): v10.4.1 got the capture path right but every attempt still ended with the device answering `ERR SHOT` after the header — root cause sits in the `usb_serial_jtag` driver: the TX side is a FreeRTOS ring buffer whose items must fit contiguously, the default `tx_buffer_size` is 256 bytes, and the 2KB pixel piece therefore never enqueues (the write returns 0 instantly; the 10-byte `ERR SHOT\r\n` the host saw as "incomplete pixel data" was exactly this reply). The driver is now installed with a 4KB TX ring, pixel pieces are sent 1KB at a time, and `ERR SHOT` replies carry a reason suffix (`BUSY` / `MEM` / `HOOK` / `DATA` / `STALL` / `USB` / `SHORT`) so the web capture page can diagnose instead of retrying blind. App partition 1,048,480 -> 1,048,624 bytes (+144).
- Firmware v10.4.1 (screenshot memory fix, found on real hardware): the v10.4 `FAP_SCREENSHOT_V1` implementation buffered a whole 150KB RGB565 frame in one system-heap allocation, which the device's largest free block cannot satisfy, so every capture answered `ERR SHOT`. The capture path now streams: the flush hook copies each 20-row strip into a 3-slot ring (11.5KB per slot, 34.5KB total, ~1/4.4 of the old peak) and the USB task drains slots as they fill, with backpressure sleeps on the producer side and an abort flag shared by both sides for clean teardown. App partition 1,047,904 -> 1,048,480 bytes (+576).
- Firmware v10.4 (community publishing support): the USB serial service now implements the `FAP_SCREENSHOT_V1` observation protocol required by the AI Passport community publisher — on command the firmware wraps the display flush callback for one full-screen redraw, accumulates the native RGB565 chunks into a system-heap buffer (the 64KB LVGL pool cannot hold a 150KB full-screen frame), and streams the frame back over USB while temporarily silencing logs so no console bytes contaminate the pixel stream. Purely observational: no page state, time, or settings change. The USB task only sets a request flag; hook install/remove and the accumulation copy all happen in the LVGL context, with an abort gate and a fallback unhook covering the timeout path. App partition grows 1,046,448 -> 1,047,904 bytes (+1.4KB).
- Firmware v10.3 (code-review follow-up, all five P3 and nine P4 findings fixed): `main.c` drops the unreachable demo menu and demo entry table — unreferenced demo pages and the Wi-Fi stack they pulled in are now linker-pruned, shrinking the app partition 1,547,216 -> 1,046,448 bytes (-32.4%; -39% cumulative vs v10.1); `time_manager` NVS writes moved out of the BLE/USB task callbacks into the LVGL timer context (dirty flags + `flush_pending()`, so flash erases can no longer stall the protocol-stack task); timezone writes gain a final ±14-hour guard (the BLE entry previously had none); `s_state` reads/writes are wrapped in a critical section, eliminating torn multi-field snapshots; a failed `ble_time_sync_stop()` now resets the initialized flag instead of leaving BLE dead until reboot; plus nine polish items (dead APIs, duplicate macros, misleading comments, fake default echo).
- Firmware v10.2 (power and size): default CPU clock 160 -> 80 MHz with DFS enabled (80 MHz busy / 40 MHz idle; SPI and I2C drivers hold PM locks automatically); new idle auto-dim (backlight drops to 20% after 90 s without a key press, any key restores instantly, stored level untouched); off-clock refresh tick relaxed from 100 ms to 250 ms; compiler optimization switched from debug (-Og) to size (-Os) and the unused 20px Montserrat font dropped — app partition shrinks 1,716,832 -> 1,547,216 bytes (-9.9%); the local `sdkconfig` is now regenerated wholesale from `sdkconfig.defaults`, so local and CI build configurations are identical from here on.
- Added the first software-design document: `docs/software-design/cyber-clock-design.md` (+ Chinese pair) covering the Cyber Clock application stack — module map, concurrency model, page state machine, time-sync data flow, NVS persistence layout, display memory budget, failure degradation, and known limitations as of firmware v10.1. Registered in the software-design index and `docs/INDEX.md`.
- Firmware v10.1 (display fixes + two low-priority asks): right-column labels (battery %, weekday, uptime, voltage) no longer collapse onto row 0 — `lv_obj_get_y()` returns placeholder coords before the first layout pass, so y is now passed explicitly; the small pixel heart had its y231 row missing, leaving a 1px transparent seam across the waist (the "incomplete heart + stray horizontal line"); factory default brightness is now 80 instead of 100; after any reset the device always comes back unsynced (the old monotonic-clock-rewind check failed on some wake paths, so a power cycle kept showing SYNCED with a frozen time), and the current time is now flushed to NVS every 5 minutes while running, capping power-loss drift at 5 minutes instead of the whole uptime; `sdkconfig.defaults` raises the LVGL pool from 32KB to 64KB (the v10 white-screen fix previously lived only in the gitignored local `sdkconfig`, so CI builds still white-screened). Prebuilt binaries and the source patch are updated to match.
